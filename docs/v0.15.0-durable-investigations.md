# AegisOps v0.15.0 — durable automatic investigation

## Execution flow

Monitoring/n8n calls `POST /incidents`. A new incident and its pending
`automatic_initial` job commit together. The API returns HTTP 201 without
calling Ollama. A duplicate open service returns the existing incident with
HTTP 200 and creates no job. A unique `(incident_id, trigger)` constraint
also enforces one initial automatic job at the database boundary.

A separately started worker claims due jobs with `FOR UPDATE SKIP LOCKED`.
The short claim transaction increments attempts, assigns a random ownership
token, and records an expiry using the database clock. The worker snapshots
the current incident measurements, commits the claim, then calls the existing
Ollama/RAG investigator outside a database transaction. Both manual and
automatic investigations reuse `investigation_service.py` for identity,
approval, root-cause, evidence and schema validation, and persistence.

The worker holds a PostgreSQL session advisory lock on the claimed job during
inference using a separate autocommit connection. Thus an expired lease does
not permit concurrent inference while the original database session remains
connected. A dead worker's lock is released when PostgreSQL detects the lost
connection; after lease expiry another worker can recover the job. The
ownership token fences stale completion and failure writes after recovery.

Success inserts the investigation and marks the job completed in one
transaction, under a job row lock. Repeating completion returns the existing
result ID. There is no separate acknowledgement transaction or window between
saving and completing. Failures update the same job with fixed sanitized
messages and exponential backoff, capped at the configured maximum. Expired
final attempts become failed. There is no automatic remediation.

## Schema and compatibility

Forward-only revision `d150b8e2a731`, following `c14a0e7d921b`, only creates
`investigation_jobs` and its constraints/index. Applied migrations and the
partial incident uniqueness index are unchanged. No existing records are
updated, deleted, backfilled, or re-investigated. Historical incidents without
a job return 404 from the new job endpoint. Duplicate ingestion of those
incidents also leaves them unchanged; manual investigation still works.

Deleting an incident without investigation history cascades to its job so
the existing deletion behavior remains available. The original investigation
foreign key continues preventing deletion of incidents with history. A result
generated after explicit incident deletion is discarded. Incident statuses
and exact-service deduplication semantics are unchanged. Separate manual
requests can intentionally create additional history alongside the one
automatic result.

## Windows startup and demonstration

Run from the repository root with the existing `.env` database settings.
Migration application is an explicit operator step; it is not part of API or
worker startup. Review the database target before applying it. Development
data must never be used by tests.

```powershell
# Explicit operator action against the intended local database:
.\.venv\Scripts\python.exe -B -m alembic upgrade head

# Terminal 1: keep the API bound to loopback.
.\.venv\Scripts\python.exe -B -m uvicorn app:app --host 127.0.0.1 --port 8001

# Terminal 2: worker, or add --once to handle at most one eligible job.
.\.venv\Scripts\python.exe -B -m worker
```

Stop the worker with Ctrl+C. SIGINT/SIGTERM stop new claims after the current
attempt finishes. Network calls have connect/read timeouts; stopping may wait
for the current attempt. A forced process termination leaves a running job
recoverable after its lease expires and PostgreSQL releases the session lock.

Ensure Ollama is running and has `qwen2.5:3b` and `nomic-embed-text` available.
To demonstrate:

```powershell
$incident = Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8001/incidents -ContentType application/json -Body '{"service":"v015-demo-service","error_rate":15,"latency":1200}'
Invoke-RestMethod "http://127.0.0.1:8001/incidents/$($incident.id)/investigation-job"
Invoke-RestMethod "http://127.0.0.1:8001/incidents/$($incident.id)/investigations"
```

Use a new service name if an open demo incident already exists. With the
worker initially stopped, the first status is pending. Start the worker and
poll until completed or failed. History then contains the validated result
with human approval required. Repeat the POST: it reuses the incident and
job. The `/docs` UI shows response codes. To demonstrate failure safely, use
the isolated mocked tests below, or deliberately configure an unavailable
model endpoint on a disposable demo environment. Failed jobs remain visible;
this milestone has no manual retry/reset endpoint. Retries are automatic
until the persisted attempt limit is reached.

`GET /incidents/{id}/investigation-job` returns one bounded status object,
attempt counts, timestamps, sanitized failure information, and result ID.
It never exposes claim tokens or exception text. Missing incidents and
historical incidents without a job return distinct 404 details.

## Docker Desktop

The optional Compose `worker` profile uses the existing Python image and
database; it adds no network listener or message broker. The API remains
published only on `127.0.0.1:8001`. Neither service applies migrations.

```powershell
docker compose build api worker
docker compose up -d db
# Explicit operator action after confirming the target:
docker compose run --rm api python -m alembic upgrade head
docker compose --profile worker up -d api worker
docker compose stop worker
```

Compose defaults `OLLAMA_BASE_URL` to `http://host.docker.internal:11434`
for Windows Docker Desktop. Container localhost cannot reach Windows
Ollama. Set `OLLAMA_BASE_URL` in the Compose interpolation environment (shell
or `.env`) to override this default; other service settings can also be set
in `.env.docker`. Host Ollama must accept the container's connection. On
Linux, supply a reachable host address or explicitly configured host gateway.
Do not publish Ollama broadly to work around connectivity problems. Compose
does not provision Ollama models or n8n; the existing n8n webhook must forward
to the appropriate reachable API ingestion address.

## Configuration

Environment is loaded at process startup. Restart to apply changes.

| Variable | Default | Allowed range / meaning |
| --- | --- | --- |
| `OLLAMA_BASE_URL` | `http://localhost:11434` | Base URL, host execution |
| `OLLAMA_CHAT_MODEL` | `qwen2.5:3b` | Generation model |
| `OLLAMA_EMBED_MODEL` | `nomic-embed-text` | Embedding model |
| `OLLAMA_CHAT_TIMEOUT_SECONDS` | 120 | Read timeout, 1–600 seconds |
| `OLLAMA_EMBED_TIMEOUT_SECONDS` | 30 | Read timeout, 1–300 seconds |
| `WORKER_POLL_SECONDS` | 2 | Idle/error interval, 0.1–60 seconds |
| `WORKER_LEASE_SECONDS` | 300 | Recovery lease, 1–3600 seconds |
| `INVESTIGATION_MAX_ATTEMPTS` | 3 | Persisted at ingestion, 1–10 |
| `WORKER_BACKOFF_SECONDS` | 5 | Initial retry delay, 0–3600 seconds |
| `WORKER_MAX_BACKOFF_SECONDS` | 300 | Retry cap, 1–3600 seconds |

Each HTTP connection has a five-second connect timeout. An attempt performs
two embedding requests plus one generation request. Read timeouts are not
whole-attempt deadlines. Choose leases and container shutdown grace periods
for the configured model latency. Each active worker uses an advisory-lock
connection plus short-lived transaction connections; size PostgreSQL's
connection budget accordingly. Queue scans examine up to 32 due rows per
cycle; an unusually large set of connected owners with expired leases can
delay later work until earlier owners finish.

## Focused tests

The existing role needs CREATE only on `aegisops_test`. Each database test
creates and cleans its generated isolated schema; public test tables and
development data are not modified. Do not run unrestricted root discovery.

```powershell
.\.venv\Scripts\python.exe -B -m pytest -p no:cacheprovider tests/test_jobs.py tests/test_migrations.py tests/test_api.py tests/test_incident.py tests/test_investigation.py -q
```

Normal tests mock generation. One subprocess test exercises the real worker
CLI and RAG HTTP clients against a loopback mock Ollama server, with its
database and search path forced to the isolated test schema. The optional
live-model test is skipped unless explicitly enabled:

```powershell
$env:AEGISOPS_REAL_MODEL_SMOKE = '1'
.\.venv\Scripts\python.exe -B -m pytest -p no:cacheprovider tests/test_jobs.py::test_optional_real_model_smoke -q
Remove-Item Env:AEGISOPS_REAL_MODEL_SMOKE
```

It uses real Ollama/RAG but only a disposable test schema. It can fail due to
missing models, resource limits, response validation, or timeouts; it is not
part of deterministic CI.

## Security and reliability boundaries

Authentication and incident-level authorization are blocking prerequisites
before remote deployment, including the new status route and existing
mutating routes. Current routes use the existing dependency-injection
boundary so authorization can be added next. Run Uvicorn on loopback and
retain Compose's loopback publication. Never put credentials into status
messages or logs. Worker errors use allowlisted fixed text and no traces.

This provides at-least-once inference attempts and one persisted automatic
result per job, not exactly-once model execution across arbitrary network
partitions. If the advisory connection disappears while a model request is
still running, recovery can repeat inference; claim tokens prevent the old
owner from persisting a stale result. A connected but hung worker blocks
recovery until its session is released. No hard whole-attempt deadline,
heartbeat monitor, or external dead-letter service is added.

The worker trusts locally supplied measurements, not live production
telemetry. RAG still re-embeds runbooks per attempt; caching and stronger
recommendation quality evaluation are later work. Approved human actions
remain external: neither API nor worker executes remediation.
